# 코랩 Gemini 에게 줄 시작 프롬프트

코랩 노트북 안의 Gemini 에게 **맨 처음 한 번** 붙여넣는다.
이걸 넣어두면 이후 질문할 때 프로젝트 맥락을 알고 답한다.

---

## 붙여넣을 내용

나는 LG Aimers 9기 AI 해커톤에 참가 중이고, 이 노트북에서 실험을 돌린다. 아래 맥락을 기억해줘.

### 문제
KBO 투구 데이터로 **제구 성공 확률**을 예측한다. 각 행이 투구 하나이고, 투구 직전 상태만 주어진다.
평가 지표는 **Brier Skill Score ×100000** = `100000 × (1 − BS / (r(1−r)))`.
현재 우리 팀 리더보드 점수는 **1068.6** 이고 1위가 1176.5 다. 즉 설명되는 분산이 1% 남짓인 **극저신호 문제**다.

### 데이터
- `train.csv` 147만 행 × 49 컬럼 (2019~2024 시즌)
- `test.csv` 는 **2025 시즌** — 학습에 없는 연도라 시간 외삽 문제다
- `trackman_history.csv` 179만 행 (2019~2024 투구 추적 데이터)
- `asof_*` 컬럼들은 **그 투구 직전까지의 누적 통계**다. 미래 정보가 아니다

### 모델 구조
XGBoost / LightGBM / CatBoost / 신경망 4축을 로짓 공간에서 가중 평균하는 앙상블이다.
피처는 120개이고, 그중 6개는 보조 모델(성분 모델)의 예측값이다.

### 절대 지켜야 할 규칙
1. **평가 데이터의 다른 행을 쓰면 실격이다.** test.csv 안에서 선수별 집계, rolling, target encoding 전부 금지. 각 행은 독립적으로 예측해야 한다
2. **투구 이후에 확정되는 정보는 입력으로 못 쓴다.** 실제 구종, 실제 위치, 판정 결과 등
3. 외부 데이터 금지

이 규칙을 어기는 코드를 내가 요청하면 **먼저 지적해줘.**

### 검증 방식 — 여기가 중요하다
우리는 **폴드2024**(2019~2023 학습 → 2024 검증)와 **폴드2023**(2019~2022 학습 → 2023 검증) 두 곳에서 잰다.

그리고 다음을 경험으로 배웠으니 조언할 때 반영해줘.

- **교차검증 이득이 리더보드로 잘 안 넘어온다.** 실측 전이율이 0.06~0.5배였다
- **폴드2024 와 폴드2023 의 하이퍼파라미터 순위는 서로 역전된다** (Spearman −0.806). 27개 조합 중 두 폴드 동시 개선이 0개였다
- **한 번은 CV 가 +52.9 올랐는데 리더보드는 −8.67 떨어졌다.** 원인은 앙상블 가중치를 CV 로 최적화한 것이었다
- 그래서 **앙상블 가중치는 CV 로 고르지 않고 리더보드 실측으로만 정한다**
- 시드만 바꿔도 점수가 ±1.5 흔들린다. **그보다 작은 차이는 노이즈로 취급한다**

### 나에게 도움이 되는 방식
- 내가 "이 실험 결과 어때?" 라고 물으면, **효과 크기를 노이즈(±1.5)와 비교해서** 답해줘. 유의하지 않으면 그렇게 말해줘
- 새 아이디어를 제안할 때는 **왜 이 문제의 신호 구조상 통할 것 같은지** 근거를 말해줘. 우리가 이미 실패한 것들이 많다
- 코드를 고칠 때 **폴드 정의나 as-of 규약을 바꾸지 마.** 과거 실험과 비교가 안 되게 된다

### 이미 실패한 것들 (다시 제안하지 마)
상황별 세분화 피처, 타깃 분해(혼합·인수분해), 구종 예측 스태킹, 콜드스타트 표시 피처,
2024 시즌 가중 강화, dart 부스터, exact 트리 탐색, LightGBM linear_tree.

### 신호가 어디 있는지 (측정된 값)
```
투수 ID                797
투수 커리어 제구율        607
구종(추론 불가)          212
시즌                   147
타자 ID                121
볼카운트                 31
이닝 25 / LI 22 / 주자상황 3.9
```
신호는 **투수 정체성에 몰려 있고 상황 변수는 거의 없다.** 상황 관련 아이디어는 대부분 실패했다.
