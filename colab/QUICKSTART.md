## 2. 런타임 설정

`런타임 > 런타임 유형 변경 > T4 GPU` 로 바꾼다. GPU 없으면 XGBoost 실험이 10배 느리다.

## 3. 데이터 받기

`01_setup_and_data.ipynb` 의 다운로드 셀을 실행하면 된다.
아이디는 `team`, 비밀번호는 **팀 채널에서 따로 받는다** (이 저장소에 적어두지 않는다).

> **국내 PC 에서는 안 받아진다.** `lgadata.hyunku.mmv.kr` 이 국내 ISP 에서 차단된다
> (HTTP 는 warning.or.kr 로 리다이렉트, HTTPS 는 연결 리셋). 서버 문제가 아니라
> 통신망 경로 문제다. **Colab 에서는 정상 동작이 확인됐다** (HTTP 401 응답).
> 그러니 데이터는 Colab 에서 받아라. 로컬에 꼭 받아야 하면 VPN 이 필요하다.

받는 파일은 총 약 1.1GB 다.

| 파일 | 크기 | 용도 |
|---|---|---|
| `train.csv` | 352M | 학습 데이터 |
| `trackman_history.csv` | 338M | 트랙맨 과거 로그 |
| `X98.parquet` | 175M | 파생 피처 캐시 |
| `features.parquet` | 174M | 파생 피처 캐시 |
| `aligned.parquet` | 52M | 트랙맨 정렬 결과 |
| `oof_comp.parquet` | 30M | 성분 OOF 피처 |
| 기타 | 5M | tm5, pitcher_map, test, sample_submission |

**파생 캐시를 같이 받는 이유**: 직접 만들면 40~65분 걸린다. 받으면 3~6분이다.

받은 뒤 `MANIFEST.txt` 로 체크섬을 검증한다. 노트북에 셀이 들어있다.

## 3-1. 런타임이 노트북마다 다르다 (중요)

코랩은 **노트북마다 별개의 VM** 을 띄운다. `01` 에서 받아둔 파일은
`03` 을 열면 그 VM 에 없다. 매번 1.1GB 를 다시 받아야 하는 것처럼 보인다.

그래서 **모든 노트북 맨 위에 부트스트랩 셀**이 있다. 이 셀이
**로컬 → Drive → 데이터 서버** 순으로 찾아서 없는 것만 확보하고,
서버에서 받은 건 Drive 에 백업한다.

즉 **처음 한 번만 서버에서 받고, 이후로는 Drive 에서 복사**해온다 (30초~2분).
노트북을 바꾸든 런타임이 끊기든 부트스트랩 셀만 실행하면 된다.

> Drive 용량이 부족하면 이게 실패한다. `MyDrive/lga/` 에 약 1.1GB 가 필요하다.

## 4. 실험 돌리기

`03_run_experiments.ipynb` 를 열고 맨 위 한 줄만 고친다.

```python
RUNNER_NAME = "본인이름"
```

그 다음은 프리셋 셀을 실행하면 된다. 조합 하나가 끝날 때마다 이런 블록이 찍힌다.

```
════════════════════════════════════════════════════════════
아이디어  : XGB depth 스윕 (max_depth=8)
분류      : hparam        실행자: 홍길동         시드: 3
────────────────────────────────────────────────────────────
            폴드2024          폴드2023
기준선           867.8 ±1.5     812.4 ±1.7
결과            869.7          808.1
효과             +1.9           -4.3
유의성         ±2.2   (2se)   ±2.5   (2se)
            노이즈             기각
────────────────────────────────────────────────────────────
판정      : 보류 — 폴드 불일치
════════════════════════════════════════════════════════════
```

**판정만 보면 된다.**

| 판정 | 뜻 |
|---|---|
| 채택 후보 | 두 폴드 모두 유의하게 개선. 제출 후보 |
| 보류 | 폴드끼리 엇갈림. 판단 불가 |
| 노이즈 | 차이가 시드 흔들림 범위 안. 효과 없음 |
| 기각 | 유의하게 나빠짐 |

## 5. 결과 공유

결과는 자동으로 Drive 의 `ledger_<본인이름>.csv` 에 쌓인다.
`04_summary.ipynb` 를 돌리면 팀 전체 원장을 합쳐서 **보고용 마크다운**을 뽑아준다.
그걸 그대로 팀 채널에 붙여넣으면 된다.

## 6. 코랩 주의사항

- **런타임이 자주 끊긴다.** 조합마다 즉시 원장에 기록되므로, 끊겨도 이전 결과는 남는다. 다시 실행하면 이미 한 조합은 건너뛴다
- **무료 티어 RAM 12GB 가 빠듯하다.** `train.csv` 147만 행을 다루므로, 데이터 준비는 단계를 나눠 돌리고 사이에 런타임을 재시작한다
- **GPU 사용량 제한이 있다.** 오래 돌리면 잘린다. 한 세션에 5~10 조합 정도가 현실적이다

## 7. 반드시 알아둘 것

1. **CV 이득을 리더보드 이득으로 착각하지 마라.** 실측 전이율은 0.06~0.5배였고, 어떤 변경은 CV 가 올랐는데 LB 가 내려갔다
2. **폴드2024 와 폴드2023 의 순위는 서로 역전된다** (Spearman −0.806). "채택 후보" 도 LB 개선을 보장하지 않는다. 후보일 뿐이다
3. **블렌드 가중치는 CV 로 고르지 않는다.** 동일 모델에서 CV +14.2 인데 LB −11.66 이었다. 가중치는 리더보드로만 정한다
