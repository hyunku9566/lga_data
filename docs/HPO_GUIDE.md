## 0. 먼저 알아야 할 것 — 기대값이 낮다

솔직하게 적는다. **모델 설정 변경은 v7 이후 7전 7패다.**

| 제출 | 변경 | CV | LB |
|---|---|---|---|
| v10 | 블렌드 집중 | +14.2 | **-11.66** |
| v10a | XGB HPO | +48.0 | +2.99 |
| v11a | NN 가중 | — | -1.2 |
| v11c | 멀티태스크 | — | -0.9 |
| v12 | 카운트 상호작용 | — | -3.3 |
| v13 | CatBoost 튜닝 | — | -2.4 |
| **v17** | **LGB/CB 재튜닝** | **+6.9** | **-5.84** |

v10a(+2.99) 하나 빼면 전부 마이너스다. 반면 **피처 추가**는 통했다 (`pbc_*` CV +6.1 -> LB **+3.30**).

**그래서 HPO 는 "큰 이득을 기대하는 작업" 이 아니라 "이미 튜닝된 지점이 여전히 최적인지 확인하는 작업"으로 다뤄라.**
스윕에서 CV +40 이 나와도 LB 기대값은 0 근처다. `experiment.py` 의 `TRANSFER` 가 그 값으로 맞춰져 있다.

## 1. 가장 흔한 실패 — 낡은 기준선에 대고 재는 것

**순정 baseline(586.97)이나 v10a 시절 설정에 대고 재면 그 수치는 전이되지 않는다.**

실제 사례가 두 건 있다.
- 팀원 ablation 보고서: 순정 baseline 기준으로 "베이지안 스무딩 +206점" 이 나왔다.
  그런데 본선 파이프라인은 이미 `K=150` + `ks=[25,75,400,1000]` 로 그걸 하고 있다. 이득 0.
- `experiment.py` 의 `DEFAULT_XGB` 가 2026-08-22 까지 **v10a 시절(d6/mcw1500/n600)** 로 박혀 있었다.
  그 기준으로 스윕하면 이미 채택된 +48 을 다시 세게 된다.

**규칙: 기준선은 항상 현재 제출본이다.**
- 피처: `lib_lga.build_v16()` → **124개** (v7 120 + pbc 4). `build_v7()` 120개는 낡았다.
- XGB: `experiment.DEFAULT_XGB` (d10 / mcw6000 / n2000 / lr.005)
- LGB: `experiment.CURRENT['lgb']` (leaves15 / mcs6000 / cs0.5)
- CB: `experiment.CURRENT['cb']` (d6 / n2000 / lr.03)

`run_experiment()` 는 기본값이 이미 위로 맞춰져 있다. **`features=` 를 직접 넘기지 마라.**

## 2. 코랩에서 돌리는 법

```
https://colab.research.google.com/github/hyunku9566/lga_data/blob/main/colab/05_hpo.ipynb
```

1. `런타임 > 런타임 유형 변경 > T4 GPU`
2. 맨 위 부트스트랩 셀에서 `RUNNER_NAME` 에 **본인 이름**을 넣고 실행 (원장이 사람별로 갈린다)
3. 스윕 셀 실행
4. 마지막 셀이 원장을 커밋·푸시한다

데이터는 부트스트랩이 알아서 확보한다 (로컬 → Drive → 데이터 서버 순). 자세한 건 [`colab/QUICKSTART.md`](../colab/QUICKSTART.md).

기본 사용법:

```python
from experiment import run_experiment, CURRENT

run_experiment(
    name   = 'xgb_depth_재확인',
    kind   = 'hparam',
    grid   = {'max_depth': [8, 10, 12], 'min_child_weight': [3000, 6000, 12000]},
    model  = 'xgb',
    seeds  = 3,
    runner = RUNNER_NAME,
)
```

`model='lgb'` / `'cb'` 로 부스터를 바꾼다. **LGB/CB 는 XGB 기준선(≈873)과 직접 비교하면
델타가 -30 처럼 나와 무의미하다.** `ref_params` 를 안 넘기면 해당 부스터의 현행 설정이
자동으로 자기 기준선이 되므로 그냥 두면 된다.

## 3. 판정 규칙 — 노이즈 막대 없는 델타는 보고하지 않는다

`run_experiment` 가 시드 표준편차로 표준오차(se)를 만들어 자동 판정한다.

| 판정 | 조건 |
|---|---|
| **채택후보** | `delta > 2·se` 이고 **폴드2024·폴드2023 둘 다 양수** |
| 보류 | `delta > 2·se` 인데 한쪽만 양수 |
| 노이즈 | `\|delta\| < 2·se` |
| 기각 | `delta < -2·se` |

왜 이렇게까지 하냐면 — 폴드2024 CV **+52.9** 를 믿고 제출했다가 LB **-8.67** 을 맞았다.
그 +52.9 의 상당 부분이 27개 조합에서 최고를 고른 **선택 편향**이었고 일부는 시드 노이즈였다.

**시드는 최소 3개.** 2개면 se 가 너무 커서 대부분 '노이즈' 로 나온다.

> **폴드2023 양수가 성공을 보장하지는 않는다.** `pc_*` 는 두 폴드 다 양수였는데 LB -1.52,
> v17 도 두 폴드 다 양수였는데 LB -5.84 였다. 반대로 XGB HPO 는 폴드2024 만 양수(+45.8 / -32.9)
> 였는데 LB +2.99 였다. **두 폴드 동시 개선은 필요조건이지 충분조건이 아니다.**

## 5. 아직 안 건드린 것 — 여기부터 해라

우선순위 순이다.

### (1) NN 축 재튜닝 — 유일하게 방치된 축
기존 NN 설정은 **트리가 810 이던 시절**에 골라졌다. 지금 트리는 873 이고 NN 축 단독은 755 다.
다만 천장이 낮다는 것을 알고 시작해라 — 2026-08-22 실측:

| NN 축 | 단독 | 블렌드 w=0.10 | w=0.20 | w=0.30(현행) |
|---|---|---|---|---|
| FT-Transformer | 776.9 | **+1.6** | +0.6 | -3.1 |
| 현행 nnL3 | 484.5 | +0.3 | -8.5 | -26.4 |

**아무리 좋은 NN 을 얹어도 폴드2024 기준 +2 가 천장이다.** 대신 **NN 가중치를 .30 -> .20 으로
내리는 것**은 `FINDINGS.md` 8절에 두 폴드 동시 최적으로 이미 적혀 있고 아직 제출된 적이 없다.

### (2) 시드 수 / 앙상블 다양성
같은 설정 시드를 늘리는 것은 분산 축소라 CV/LB 부호가 뒤집힐 여지가 적다.
현행 XGB 12개, LGB 7개. 늘렸을 때의 한계효용을 재본 적이 없다.

### (3) 최근성 가중 반감기(hl)
현행 `hl=2.0`. 폴드2024 에서는 `hl=1.0` 이 **+5.6** 로 더 좋았는데, ABS 대리실험을 근거로
hl=2 를 택했다. **그런데 그 ABS 전제는 2026-08-21 에 반증됐다** (R리그에 2024 단절이 없다,
`docs/CEILING.md` 4절). **hl 은 재검토 대상이다.**
