# 검증 프로토콜

**실험을 돌리기 전에 이 문서를 읽어라.** 여기 적힌 규칙은 전부 우리가 손해를 보고 배운 것이다.

---

## 왜 이 문서가 필요한가

이 문제는 **CV 점수가 리더보드를 예측하지 못한다.** 그냥 못 맞히는 정도가 아니라, 어떤 경우엔 **부호가 반대**다.

| 변경 | CV 이득 (폴드2024) | 실제 LB 이득 | 전이율 |
|---|---|---|---|
| 멀티태스크 NN (v8) | +4.3 | +0.92 | 0.21배 |
| CatBoost (v9) | +5.3 | +2.78 | 0.52배 |
| XGB HPO (v10a) | +48.0 | +2.99 | **0.06배** |
| 블렌드 집중 (v10) | +14.2 | **−11.66** | **음수** |

CV에서 +48이 LB에서 +3이 되고, CV에서 +14가 LB에서 −12가 된다.
**CV 수치를 LB 기대치로 환산하지 마라.**

---

## 규칙

### 1. 한 번에 하나만 바꾼다

v10에서 세 가지(XGB HPO, LGB HPO, 블렌드 배분)를 한꺼번에 바꿨다. LB가 −8.67로 떨어졌는데 **어느 것이 원인인지 알 수 없었다.** 원인을 특정하려고 제출을 1회 더 써야 했고, 그 결과 HPO는 +2.99(좋음), 블렌드는 −11.66(나쁨)으로 정반대였다는 게 드러났다.

묶어서 바꾸면 실패했을 때 **되돌릴 지점을 잃는다.** 제출은 하루 5회뿐이다.

### 2. 모델 설정은 두 폴드 동시 개선일 때만 채택

`src/lib_lga.py` 의 `bench2()` 를 써라. 폴드2024와 폴드2023 양쪽을 재고 `both` 플래그를 반환한다.

```python
from lib_lga import build_v7, bench2
X = build_v7()
r = bench2(X, params, name="my_experiment")
if r["both"]:      # 두 폴드 모두 개선
    print("채택 후보")
```

한쪽 폴드만 보고 채택하는 실수가 **구조적으로 막히도록** 판정이 코드에 박혀 있다.

### 3. 블렌드 가중치는 CV로 고르지 않는다. LB 실측으로만 정한다

**근거**: 모델은 완전히 동일하고 가중치만 다른 두 설정에서,

| | 폴드2024 | LB |
|---|---|---|
| v10 배분 (XGB .70 집중) | 875.4 | 1056.94 |
| v10a 배분 (XGB .315 분산) | 861.2 | 1068.60 |
| **차이** | **+14.2** | **−11.66** |

폴드2024는 XGB 집중을 선호하고, LB는 분산을 선호한다. **두 지표의 순서가 뒤집힌다.**

폴드2022에서 재보면 LB와 같은 방향이 나온다 (분산 722.4 > 집중 709.3). 즉 폴드2024가 블렌드 배분에 대해서만 특이하게 거동한다.

**분리 운영**: 모델 학습 설정(HPO·피처)은 CV로 후보를 좁히되 채택은 두 폴드 동시 개선으로, **블렌드 가중치는 LB 실측으로만.**

### 4. 폴드2022는 모델 설정 선택에 쓰지 않는다

2024 시즌부터 데이터 거동이 다르다. 원인은 ABS(자동 볼판정) 도입으로 **추정**하지만 **확증되지 않았다** — 월별 제구율에 2024 시즌 시작 지점의 단절이 없다(2023년 4월 .4858 < 2024년 3월 .5038).

원인이 무엇이든 **2025와 시간적으로 가장 가까운 건 2024**다. 다만 규칙 5를 보라.

### 5. 어느 폴드도 LB를 대변하지 못한다

폴드2024 HPO 상위 조합들을 폴드2023에서 다시 재봤다 (`results31/res_f2023.csv`):

| 설정 | Δ폴드2023 | Δ폴드2024 | both |
|---|---|---|---|
| 현재 v9 d6/mcw1500/n600/lr.008 | (기준 799.0) | (기준 821.7) | — |
| d10/mcw6000/n600/lr.015 | **−32.5** | +41.5 | ✗ |
| d8/mcw6000/n1000/lr.008 | −29.5 | +40.3 | ✗ |
| d12/mcw6000/n1000/lr.008 | −29.1 | +39.8 | ✗ |
| mcw3000 d8/n1000/lr.008 | −12.5 | +37.5 | ✗ |
| v10 출시본 d10/mcw6000/n2000/lr.005 | −32.9 | +45.8 | ✗ |
| 27차 최고 d10/mcw6000/n4000/lr.004 | **−49.3** | +46.1 | ✗ |

**순위상관 Spearman = −0.806. 27개 조합 중 두 폴드 동시 개선은 0개.**

폴드2024에서 가장 좋았던 설정이 폴드2023에서 가장 나쁘다. 그런데 그 설정이 LB에서는 **+2.99로 (작지만) 양수**였다.

정확한 요약은 이렇다 — **폴드2024는 LB 방향을 약하게 맞히고 크기를 크게 과장한다. 폴드2023은 방향조차 반대다. 두 폴드를 모두 통과하는 설정을 찾는 건 현재 규제 강도 축(mcw)에서 거의 불가능하다.**

이 상황에서 실무적으로 할 수 있는 건:
- 두 폴드 동시 개선을 **채택 조건이 아니라 위험 신호**로 쓴다 (`both`가 ✗면 LB에서 기대치를 크게 낮춘다)
- 변화 폭이 큰 CV 이득일수록 더 의심한다
- 최종 판단은 LB 제출로 한다

### 6. 여러 번 선택한 것은 선택 편향을 의심한다

우리는 폴드2024 하나로 HPO 27개, 블렌드 가중치 격자 1908개, 피처군, 학습기 11종을 골랐다. 반복 선택이 쌓이면 그 폴드에 과적합된다. **"CV +53"이라고 보고했던 수치의 상당 부분이 허수였다.**

선택 절차가 무거울수록 전이율이 떨어진다는 게 데이터로 확인된다 (HPO 27개 중 최고 선택 → 전이율 0.06배).

## 제출 운영

- 하루 5회. **측정에 써라, 추측에 쓰지 마라.**
- 변경 하나당 제출 하나가 원칙. 여러 개를 동시에 내면 서로를 오염시키지 않지만(각각 독립 평가), **어느 조합이 좋은지는 알 수 없다.**
- 최고 기록은 남는다. 실패한 제출이 기존 최고점을 지우지 않으므로, **실험적 제출의 비용은 기회비용뿐**이다.

### 드리프트 상수 역산법 (검증된 기법)

리그 제구율이 매년 하락하는데 학습에 2025가 없어 모델이 과대 예측한다. 로짓 시프트 상수 `d` 로 레벨만 보정한다.

**제출 2회로 최적값을 역산할 수 있다.** 시프트 `δ ≈ d × r(1−r)` 에 대해

```
ΔBSS ≈ −(2δ·b + δ²) / (r(1−r)) × 1e5      (b = 예측 편향)
```

실제 사례: `d=0` 에서 1055.1587, `d=−0.035` 에서 1054.1189 → 차이 −1.04에서 **b = +0.0042** 를 역산했다. 최적 `d = −0.0169` 로 계산되어 `d=−0.020` 을 제출했고, **예측 1062.06 vs 실제 1061.9107** 로 0.15점 오차였다.

모델이 바뀌면 편향도 바뀐다. **주요 모델 변경 후에는 이 역산을 다시 하는 게 좋다.**

## 흔한 함정 (실제로 겪은 것)

### 추론 코드에서 행 독립성이 깨지는 자리
`sub[TGT] = [pm.get(r, float(p.mean())) for r in sub[ID].values]` — 폴백값으로 **전체 테스트 예측 평균**을 쓰고 있었다. 실제로 발동하진 않지만 규칙 위반 형태다. 학습 데이터에서 온 상수로 바꿨다. 자세한 건 [`RULES.md`](RULES.md).

### 로짓/확률 규약 혼동
`MTabM.forward` 는 **로짓**을 반환하는데 추론 코드가 확률로 착각해 `logit(clip(...))` 을 한 번 더 씌웠다. 로짓 −0.26이 `clip(1e-6)` 에 걸려 −13.8이 되어, 멀티태스크 NN 예측이 5행 중 3행에서 **0.0000** 이 나왔다.

**5행짜리 샘플 `test.csv` 로 로컬 실행 테스트를 안 했으면 그대로 제출됐다.** 빌드 후 반드시 로컬 추론을 돌리고 예측 평균이 상식적인지 확인해라.

### 학습/추론 피처 규약 차이는 버그가 아니다
학습은 시즌별 as-of, 추론은 전체 이력 기준이다. 학습 데이터를 추론 경로에 태워 비교하면 105개 중 65개가 불일치하는데 **정상**이다. 2024년 행을 넣으면 `p_succ_ssn_n=0` 이 되는 건 2024가 앵커 시점이기 때문이다.

### 셸에서 자기 자신을 죽이는 pkill
`pkill -f "run26.py"` 는 **그 명령을 담은 셸의 명령줄**도 매칭한다. 두 번 당했다. `pkill -f "[r]un26.py"` 처럼 패턴을 깨서 써라.

### 디렉토리보다 리다이렉트가 먼저 실행된다
`python run.py > results25/out.txt` 는 `results25/` 가 없으면 즉시 실패한다. 스크립트 안에서 `os.makedirs` 를 해도 소용없다. 셸에서 `mkdir -p` 를 먼저 하거나, 절대 경로로 리다이렉트해라.
